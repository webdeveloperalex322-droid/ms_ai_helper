# Feature Specification: Admin Panel

**Feature Branch**: `002-adminjs-admin-panel`

**Created**: 2026-07-01

**Status**: Draft

---

## Product Scope

Внутренняя веб-панель управления для операционной команды. Позволяет просматривать и редактировать загруженные товары, запускать импорт каталога, настраивать поведение ассистента и управлять пресет-подсказками. Доступна только авторизованному администратору. Клиентский трафик никак не затрагивает.

---

## Out of Scope

- Управление пользователями (нет user DB в MVP)
- Аналитические дашборды и графики
- Ролевая модель доступа (достаточно одного admin-пользователя)
- Управление городами и торговыми сетями (read-only в MVP)
- Логи ассистента (только через БД напрямую)

---

## User Scenarios & Testing

### User Story 1 — Просмотр и редактирование каталога товаров (Priority: P1)

Администратор открывает раздел «Товары» и видит список всех импортированных товаров с ценами по городам. Может отфильтровать по городу, сети, категории или статусу доступности. Может отредактировать отдельные поля (флаги доступности, метаданные) без повторного импорта.

**Why this priority**: Критически важно для операционной команды — быстро найти и скорректировать данные без обращения к разработчику.

**Independent Test**: Открыть `/admin` → перейти в Products → применить фильтр по city_br → убедиться, что отображаются только товары нужного города → изменить поле `is_available` у одного товара → убедиться, что изменение отражается в БД.

**Acceptance Scenarios**:

1. **Given** в БД есть товары для нескольких городов, **When** администратор открывает список товаров и фильтрует по `br`, **Then** отображаются только товары с указанным `br`.
2. **Given** отображён список товаров, **When** администратор меняет поле `is_available = false` и сохраняет, **Then** изменение сохранено в БД и ассистент перестаёт показывать товар.
3. **Given** в каталоге тысячи товаров, **When** администратор открывает список, **Then** данные отображаются с пагинацией — страница загружается менее чем за 3 секунды.

---

### User Story 2 — Запуск и мониторинг импорта каталога (Priority: P1)

Администратор переходит в раздел «Импорт», видит историю последних заданий с их статусами и результатами. Может запустить новый импорт городов или товаров. Может отследить прогресс текущего задания.

**Why this priority**: Без управления импортом каталог устаревает — ключевая операционная задача.

**Independent Test**: Открыть раздел Import Jobs → создать новое задание `import cities` → убедиться, что запись появилась со статусом `running` → дождаться завершения → статус сменился на `success` или `failed` с деталями.

**Acceptance Scenarios**:

1. **Given** ни одного задания не запускалось, **When** администратор нажимает «Запустить импорт городов», **Then** в таблице `import_jobs` появляется новая запись, запрос к внешнему API отправлен.
2. **Given** задание запущено, **When** администратор обновляет страницу, **Then** отображаются `status`, `started_at`, количество обработанных записей.
3. **Given** внешний API вернул ошибку, **When** задание завершилось с `partial_failed`, **Then** в деталях задания виден текст ошибки, старые данные в каталоге сохранены.

---

### User Story 3 — Настройка параметров ассистента (Priority: P1)

Администратор открывает раздел «Настройки» и может редактировать правила ассистента: список запрещённых фраз, приоритетные товары, максимальное число карточек в ответе, правила тональности.

**Why this priority**: Контентная и поведенческая настройка ассистента без деплоя — базовая операционная потребность.

**Independent Test**: Открыть Admin Rules → добавить фразу в `banned_phrases` → сохранить → выполнить `POST /v1/assistant/product-answer` с ответом содержащим эту фразу → убедиться, что фраза удалена из ответа ассистентом.

**Acceptance Scenarios**:

1. **Given** в `admin_rules` пустой список `banned_phrases`, **When** администратор добавляет запрещённую фразу и сохраняет, **Then** ассистент удаляет эту фразу из всех последующих ответов.
2. **Given** в `admin_rules` установлено `max_cards_in_response = 3`, **When** ассистент формирует ответ, **Then** в ответе не более 3 карточек товаров.
3. **Given** администратор указал приоритетные `product_id`, **When** ассистент формирует shortlist при подходящем запросе, **Then** приоритетные товары получают boost в скоринге.

---

### User Story 4 — Управление пресет-подсказками (Priority: P2)

Администратор открывает раздел «Подсказки» и видит все пресет-подсказки с их статусами. Может изменить текст, payload, правила видимости или деактивировать подсказку без деплоя.

**Why this priority**: Операционная гибкость — редактирование подсказок без программиста.

**Independent Test**: Открыть Suggestions → изменить `title` у одной подсказки → сохранить → выполнить `GET /v1/assistant/suggestions` → убедиться, что `title` обновлён в ответе API.

**Acceptance Scenarios**:

1. **Given** подсказка активна (`enabled = true`), **When** администратор устанавливает `enabled = false` и сохраняет, **Then** подсказка перестаёт возвращаться в `GET /suggestions`.
2. **Given** подсказка имеет `availability_rules` с `allowed_br`, **When** администратор меняет список городов, **Then** изменение применяется при следующем запросе `/suggestions`.
3. **Given** список из 21 подсказки, **When** администратор открывает раздел, **Then** все подсказки отображаются с сортировкой по `sort_order`.

---

### Edge Cases

- Неверные credentials при входе → 401, доступ к `/admin` закрыт.
- Попытка удалить запись, на которую ссылаются другие таблицы → отображается понятная ошибка, запись не удалена.
- Параллельное редактирование одной записи двумя сессиями → последнее сохранение побеждает (last-write-wins).
- Запуск импорта когда уже есть активное задание → система допускает параллельный запуск или сообщает об уже запущенном.

## Requirements

### Functional Requirements

- **FR-001**: Система ДОЛЖНА предоставлять защищённый веб-интерфейс по пути `/admin`, доступный только с валидными учётными данными.
- **FR-002**: Аутентификация ДОЛЖНА работать на основе credentials из переменных окружения (`ADMIN_USER`, `ADMIN_PASSWORD`) — без отдельной таблицы пользователей.
- **FR-003**: Интерфейс ДОЛЖЕН предоставлять CRUD-операции (просмотр, создание, редактирование, удаление) для таблиц: `products`, `city_products`, `assistant_suggestions`, `admin_rules`.
- **FR-004**: Интерфейс ДОЛЖЕН предоставлять просмотр (read-only) для таблиц: `import_jobs`, `cities`, `retail_networks`.
- **FR-005**: Раздел `import_jobs` ДОЛЖЕН поддерживать запуск новых заданий импорта (cities / products) через действие в интерфейсе.
- **FR-006**: Списки товаров ДОЛЖНЫ поддерживать фильтрацию по `br` (город), `rn` (сеть), `is_available`, `is_valid`.
- **FR-007**: Все список-представления ДОЛЖНЫ поддерживать пагинацию и сортировку по ключевым полям.
- **FR-008**: Интерфейс ДОЛЖЕН отображать корректные метки полей на русском языке вместо технических имён колонок.
- **FR-009**: JSON-поля (например, `payload`, `banned_phrases`, `availability_rules`) ДОЛЖНЫ отображаться и редактироваться как структурированные данные (не как raw строка).
- **FR-010**: Удаление записей ДОЛЖНО запрашивать подтверждение.

### Key Entities

- **Product**: глобальная карточка товара — название, состав, КБЖУ, теги, флаги валидности.
- **CityProduct**: городовая проекция — цена, доступность, привязка к городу и target.
- **ImportJob**: задание импорта — тип, статус, время начала/окончания, счётчики, текст ошибки.
- **AdminRule**: правила ассистента — banned_phrases, max_cards, priority_products, тональность.
- **AssistantSuggestion**: пресет-подсказка — title, payload, enabled, sort_order, availability_rules.
- **City**: город — br, название, rn.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Администратор может найти нужный товар по фильтру города менее чем за 30 секунд.
- **SC-002**: Страница списка товаров загружается менее чем за 3 секунды при каталоге от 10 000 записей.
- **SC-003**: Изменение `banned_phrases` в интерфейсе отражается в поведении ассистента в следующем же запросе.
- **SC-004**: Администратор может запустить импорт и увидеть его статус без обращения к разработчику.
- **SC-005**: Все разделы доступны без технической документации — поля имеют читаемые русские метки.

---

## Assumptions

- Выбранная технология: AdminJS (`adminjs` + `@adminjs/nestjs` + `@adminjs/drizzle`) — монтируется как NestJS-модуль, читает Drizzle-схему.
- Аутентификация: HTTP Basic Auth через middleware AdminJS — достаточно для MVP внутренней панели.
- Один администратор — roteName-based multi-user access вне скоупа MVP.
- Таблицы `product_chunks`, `product_embeddings`, `ai_logs`, `assistant_sessions` скрыты из панели (только для разработчиков).
- Запуск импорта через панель реализуется через Custom Action в AdminJS, вызывающий внутренний NestJS endpoint.
- Данные `import_jobs` только для чтения — создание через Custom Action, редактирование руками невозможно.
- Редактирование `city_products` ограничено флагами — изменение цен через панель не предусмотрено (цены обновляются импортом).
