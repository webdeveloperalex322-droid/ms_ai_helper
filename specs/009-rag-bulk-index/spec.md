# Feature Specification: Массовая индексация каталога для векторного поиска

**Feature Branch**: `009-rag-bulk-index`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "Массовая индексация RAG: CLI-скрипт, который обходит все строки city_products и для каждой строит searchable-text chunk + эмбеддинг. Фильтры по rn/br/target, батчевая обработка с ограничением конкурентности, пропуск уже проиндексированных, --force, ретраи с backoff, прогресс и итоговый отчёт, ненулевой exit code при ошибках, --dry-run."

> Проблема: массового индексатора в проекте нет. Существует только индексация одного товара по идентификатору. В результате векторное представление каталога пустое или частичное, гибридный поиск деградирует до поиска по ключевым словам, а при пустом множестве кандидатов ассистент уходит в запасной сценарий «все товары города». Ответы формально возвращаются, но релевантность подбора не обеспечена.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Первичная индексация всего каталога (Priority: P1)

Оператор после импорта каталога запускает одну команду и получает полностью проиндексированный каталог: для каждой позиции каталога в каждом городе и на каждой витрине построено поисковое представление и его векторное представление. По окончании оператор видит отчёт: сколько позиций обработано, сколько пропущено, сколько завершилось ошибкой, сколько времени заняло.

**Why this priority**: Без этого сценария смысловой поиск не работает вообще. Все остальные сценарии — оптимизация повторных запусков.

**Independent Test**: На базе со свежеимпортированным каталогом и пустым набором векторов запустить команду без аргументов; убедиться, что после завершения все позиции каталога имеют состояние «готово», а смысловой поиск возвращает непустой список кандидатов.

**Acceptance Scenarios**:

1. **Given** каталог импортирован и ни одна позиция не проиндексирована, **When** оператор запускает массовую индексацию без аргументов, **Then** обрабатываются все позиции каталога во всех сочетаниях сети/города/витрины, и по завершении число позиций в состоянии «готово» равно числу позиций каталога.
2. **Given** индексация завершена, **When** оператор задаёт ассистенту продуктовый вопрос, **Then** подбор кандидатов выполняется смысловым поиском, а не запасным сценарием «все товары города».
3. **Given** индексация выполняется, **When** оператор наблюдает вывод, **Then** он периодически видит текущее число обработанных позиций, число оставшихся и оценку времени до завершения.
4. **Given** индексация завершилась без ошибок, **When** оператор проверяет код завершения команды, **Then** код равен нулю.

---

### User Story 2 - Частичная переиндексация по срезу каталога (Priority: P2)

Оператор изменил данные по одному городу или одной витрине и не хочет ждать обхода всего каталога. Он ограничивает область работы сетью, городом и/или витриной и индексирует только этот срез.

**Why this priority**: Полный обход каталога дорог по времени и по обращениям к платному поставщику векторных представлений. Без срезов оператор вынужден платить за полный проход ради одного города.

**Independent Test**: Запустить команду с ограничением по одному городу; убедиться, что затронуты только позиции этого города, а состояние позиций других городов не изменилось.

**Acceptance Scenarios**:

1. **Given** каталог содержит несколько городов, **When** оператор запускает индексацию с ограничением по одному городу, **Then** обрабатываются только позиции этого города, а отчёт называет применённое ограничение.
2. **Given** заданы одновременно ограничения по сети, городу и витрине, **When** команда запущена, **Then** обрабатывается только пересечение этих ограничений.
3. **Given** заданному ограничению не соответствует ни одна позиция каталога, **When** команда запущена, **Then** оператор получает явное сообщение о пустой выборке и ненулевой код завершения, отличающий этот случай от ошибки обработки.

---

### User Story 3 - Дешёвый повторный запуск (Priority: P2)

Оператор запускает индексацию регулярно, например после каждого импорта. Позиции, содержимое которых не изменилось с прошлого раза и которые уже проиндексированы тем же способом, повторно не обрабатываются. При необходимости оператор может потребовать полной переобработки.

**Why this priority**: Регулярный запуск станет частью эксплуатации; без пропуска неизменившихся позиций каждый запуск повторно оплачивает весь каталог.

**Independent Test**: Выполнить индексацию дважды подряд без изменений данных; во втором запуске все позиции должны попасть в категорию «пропущено», а число обращений к поставщику векторных представлений должно быть нулевым.

**Acceptance Scenarios**:

1. **Given** каталог полностью проиндексирован и не менялся, **When** оператор повторяет запуск, **Then** все позиции отнесены к пропущенным, обращений к поставщику векторных представлений не происходит, код завершения нулевой.
2. **Given** у части позиций изменились данные, влияющие на поисковое представление, **When** оператор повторяет запуск, **Then** переобрабатываются только изменившиеся позиции.
3. **Given** каталог проиндексирован одним способом получения векторов, **When** способ изменён и запуск повторён, **Then** все позиции переобрабатываются, поскольку прежние векторы несопоставимы с новыми.
4. **Given** каталог полностью проиндексирован, **When** оператор запускает команду с требованием полной переобработки, **Then** обрабатываются все позиции выборки независимо от их прежнего состояния.

---

### User Story 4 - Устойчивость к сбоям поставщика векторов (Priority: P2)

Внешний поставщик векторных представлений периодически отвечает ошибкой или ограничением частоты запросов. Индексация не прекращается на первой ошибке: неудачная позиция повторяется несколько раз с нарастающей паузой, а если так и не удалась — помечается неуспешной, и обход продолжается.

**Why this priority**: Обход каталога длителен; падение всего прогона из-за единичной сетевой ошибки делает инструмент непригодным.

**Independent Test**: Смоделировать поставщика, отвечающего ошибкой на первые попытки и успехом на последующие; убедиться, что позиция в итоге проиндексирована и прогон завершён успешно.

**Acceptance Scenarios**:

1. **Given** поставщик отвечает ошибкой на первые попытки, **When** идёт обработка позиции, **Then** попытка повторяется с нарастающей паузой, и при успехе позиция считается обработанной.
2. **Given** поставщик отвечает ошибкой на все попытки для одной позиции, **When** лимит попыток исчерпан, **Then** позиция помечается неуспешной, обход остальных позиций продолжается.
3. **Given** прогон завершился и часть позиций неуспешна, **When** оператор проверяет вывод, **Then** отчёт содержит число неуспешных позиций и перечень их идентификаторов, а код завершения ненулевой.
4. **Given** прогон прерван оператором, **When** обработка останавливается, **Then** уже обработанные позиции сохраняют состояние «готово», и повторный запуск продолжает с необработанных.

---

### User Story 5 - Предварительная оценка объёма работ (Priority: P3)

Перед длительным и платным прогоном оператор хочет узнать, сколько позиций будет обработано и сколько пропущено, не изменяя данные и не обращаясь к платному поставщику.

**Why this priority**: Снижает риск случайного дорогого прогона, но сам по себе ценности не создаёт.

**Independent Test**: Запустить команду в режиме предварительной оценки на проиндексированной базе; убедиться, что данные не изменились и обращений к поставщику не было.

**Acceptance Scenarios**:

1. **Given** задан режим предварительной оценки, **When** команда запущена, **Then** выводится число позиций к обработке и к пропуску, при этом ни одна запись не изменена и обращений к поставщику векторных представлений не произошло.
2. **Given** заданы ограничения по срезу и режим предварительной оценки, **When** команда запущена, **Then** оценка учитывает ограничения.

---

### Edge Cases

- Каталог содержит десятки тысяч позиций — обход не должен требовать одновременной загрузки всего каталога в память; выборка обрабатывается порциями.
- Позиция каталога ссылается на товар, у которого отсутствуют описание и состав — поисковое представление строится из доступных полей, позиция не считается ошибочной.
- Поставщик векторных представлений возвращает вектор неожиданной размерности — позиция помечается неуспешной с внятным сообщением, прогон продолжается.
- Соединение с хранилищем потеряно в середине прогона — команда завершается ненулевым кодом с явным сообщением, уже сохранённые результаты остаются в силе.
- Одна и та же позиция каталога встретилась в выборке дважды в пределах прогона — обрабатывается один раз, дублирующих записей не появляется. Защита от двух одновременно запущенных прогонов на одной базе в объём не входит (см. Assumptions).
- Ограничение задано с опечаткой в идентификаторе — выборка пуста, оператор получает сообщение об этом, а не молчаливый успешный прогон.
- Оператор указал степень параллелизма выше допустимой — значение ограничивается сверху, оператор предупреждён.
- Развёрнутая среда собрана без инструментов разработки и без исходных текстов — команда всё равно доступна оператору и запускается тем же способом, что и остальные обслуживающие операции этой среды.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять оператору команду массовой индексации, обрабатывающую все позиции каталога, доступные в каждом сочетании сети, города и витрины.
- **FR-002**: Для каждой позиции система MUST построить актуальное поисковое текстовое представление и связанное с ним векторное представление, а также зафиксировать итоговое состояние позиции: «готово» или «неуспешно».
- **FR-003**: Система MUST позволять ограничивать выборку по сети, городу и витрине — по отдельности и в любом сочетании.
- **FR-004**: Система MUST по умолчанию пропускать позиции, для которых уже существует векторное представление, построенное для того же содержимого и тем же способом.
- **FR-005**: Система MUST предоставлять режим полной переобработки, игнорирующий правило пропуска.
- **FR-006**: Система MUST обрабатывать выборку порциями с ограниченной степенью одновременности, настраиваемой оператором и ограниченной сверху безопасным значением.
- **FR-007**: Система MUST повторять неудачные обращения к поставщику векторных представлений ограниченное число раз с нарастающей паузой между попытками.
- **FR-008**: Единичная неуспешная позиция MUST NOT прерывать прогон; она помечается неуспешной, и обход продолжается.
- **FR-009**: Система MUST периодически выводить ход выполнения: число обработанных, пропущенных и неуспешных позиций, общий объём выборки и оценку оставшегося времени.
- **FR-010**: По завершении система MUST вывести итоговый отчёт: объём выборки, число обработанных, пропущенных, неуспешных позиций, длительность прогона и перечень идентификаторов неуспешных позиций.
- **FR-011**: Система MUST завершаться нулевым кодом, если неуспешных позиций нет, и ненулевым — если они есть, а также при пустой выборке и при нештатном завершении; коды завершения для этих случаев MUST различаться.
- **FR-012**: Система MUST предоставлять режим предварительной оценки, который сообщает объём предстоящей работы, не изменяя данные и не обращаясь к поставщику векторных представлений.
- **FR-013**: Система MUST выводить в начале прогона применённые параметры: способ получения векторов, ограничения выборки, степень одновременности, режим переобработки.
- **FR-014**: Система MUST работать с любым из поддерживаемых проектом способов получения векторных представлений, включая полностью автономный, не требующий внешних обращений.
- **FR-015**: Повторный запуск после прерывания MUST продолжать работу с необработанных позиций без потери ранее сохранённых результатов.
- **FR-016**: Система MUST NOT выводить в журнал прогона значения ключей доступа к внешним сервисам.
- **FR-017**: Команда MUST быть доступна оператору в развёрнутой среде — той, где приложение работает из собранного артефакта. Запуск MUST NOT требовать установки инструментов разработки, доставки исходных текстов или изменения состава зависимостей этой среды.
- **FR-018**: Способ запуска команды в развёрнутой среде MUST совпадать по форме с уже принятым в проекте способом запуска обслуживающих операций (применение миграций), чтобы оператор не заучивал отдельный порядок действий.

### Key Entities

> Соответствие терминов спеки идентификаторам предметной области («сеть», «город», «витрина») зафиксировано в [docs/knowledge/glossary.md](../../docs/knowledge/glossary.md).

- **Позиция каталога в городе**: доступность конкретного товара в конкретном городе и на конкретной витрине; единица обхода при индексации.
- **Поисковое представление позиции**: текст, собранный из полей товара, по которому ведётся поиск; хранит отпечаток содержимого и состояние индексации.
- **Векторное представление**: числовой образ поискового представления, привязанный к нему, к способу получения и к отпечатку содержимого.
- **Отчёт прогона**: сводка результата — объём выборки, обработано, пропущено, неуспешно, длительность, перечень неуспешных позиций.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После одного запуска команды на свежеимпортированном каталоге доля позиций в состоянии «готово» составляет не менее 99% при доступном поставщике векторных представлений.
- **SC-002**: Продуктовые вопросы ассистенту после индексации обслуживаются смысловым подбором кандидатов; доля ответов, построенных на запасном сценарии «все товары города», не превышает 1% на контрольном наборе вопросов.
- **SC-003**: Повторный запуск на неизменившемся каталоге не порождает ни одного обращения к поставщику векторных представлений и завершается не более чем за 25% времени первичного прогона. Порог отражает неустранимую цену инкрементальности: чтобы решить, что работы нет, команда всё равно читает все позиции каталога и считает отпечатки их содержимого. Обращений к поставщику при этом ровно ноль — это и есть основная экономия.
- **SC-004**: Каталог из 10 000 позиций индексируется за один прогон без ручного вмешательства и без исчерпания памяти.
- **SC-005**: При недоступности поставщика векторных представлений на отдельных позициях прогон доходит до конца и сообщает точный перечень неуспешных позиций в 100% случаев.
- **SC-006**: Оператор способен запустить индексацию одного города, ни разу не заглянув в исходный код, опираясь только на справку команды.
- **SC-007**: Оператор запускает индексацию на развёрнутом экземпляре одной командой, не устанавливая в этой среде ничего дополнительно и не копируя туда исходные тексты.
- **SC-008**: Каталог развёрнутого экземпляра переходит из состояния «векторных представлений нет» в состояние «не менее 99% позиций готовы» за один сеанс работы оператора, без правок в развёрнутой среде.

## Assumptions

- Каталог уже импортирован; наполнение каталога и его индексация — разные операции, и данная спека покрывает только вторую.
- Инструмент предназначен для оператора с доступом к серверу приложения; веб-интерфейс и запуск по расписанию в объём не входят.
- Развёрнутая среда несёт только собранный артефакт приложения и его рабочие зависимости — инструментов разработки там нет. Поэтому команда должна попадать в артефакт сборки наравне с прочими обслуживающими операциями, а не запускаться из исходных текстов.
- Порядок обновления развёрнутой среды (доставка нового артефакта) существует и остаётся вне объёма этой спеки; фича лишь требует, чтобы команда оказалась в артефакте.
- Правило пропуска опирается на отпечаток содержимого поискового представления и на идентификатор способа получения векторов — обе величины уже сохраняются существующей моделью данных.
- Значения по умолчанию: позиции обрабатываются пачками по 32, одновременно в работе не более 3 пачек, число попыток на пачку — 3, паузы между попытками нарастают экспоненциально начиная с 1 секунды.
- Коды завершения: 0 — успех, 1 — нештатное завершение, 2 — пустая выборка, 3 — прогон завершён, но есть неуспешные позиции.
- Обход выполняется в рамках одного процесса; распределённый прогон и очередь заданий в объём не входят. Защита от двух одновременно запущенных процессов на одной базе за скоп вынесена: инструмент запускается оператором вручную. Внутри одного прогона повторная обработка одной и той же позиции исключена дедупликацией.
- Инструмент повторяет стиль существующего скрипта индексации одного товара: автономный запуск, конфигурация из окружения проекта.
- Удаление устаревших представлений для позиций, исчезнувших из каталога, в объём не входит.
