# Contract — Configuration

**Feature**: [../spec.md](../spec.md) | **Data model**: [../data-model.md](../data-model.md)

Контракт между сервисом и развёртыванием. Все переменные добавляются в zod-схему `src/config/configuration.ts` — прямых обращений к `process.env` не вводится (конвенция `CLAUDE.md`).

---

## Новые переменные

| Переменная | Тип | Дефолт | Обязательна в продакшене |
|---|---|---|---|
| `CLIENT_API_KEYS` | список `метка:ключ` через запятую | `dev-client:dev-client-key-change-in-prod` | **Да** |
| `ACCESS_CONTROL_MODE` | `enforce` \| `observe` | `enforce` | Нет |
| `CORS_ALLOWED_ORIGINS` | список источников через запятую | пусто (в разработке трактуется как «любой») | **Да** |
| `THROTTLE_COSTLY_LIMIT` | целое | консервативное | Нет |
| `THROTTLE_COSTLY_TTL_SEC` | целое | 60 | Нет |
| `THROTTLE_STANDARD_LIMIT` | целое | консервативное | Нет |
| `THROTTLE_STANDARD_TTL_SEC` | целое | 60 | Нет |
| `TRUST_PROXY` | булево | `false` | **Да** — `true` за nginx |
| `BODY_LIMIT_BYTES` | целое | 1048576 | Нет |

Числовые пороги частоты спецификацией не фиксируются (FR-013) — подбираются на реальном трафике. Дефолты выбираются заведомо консервативными.

---

## Изменения в существующих переменных

Схема **сохраняет дефолты** для `INTERNAL_API_KEY`, `ADMIN_USER`, `ADMIN_PASSWORD`, `ADMIN_COOKIE_SECRET` (`configuration.ts:32-40`) — их удаление сломало бы разработку и существующие тесты (FR-020). Добавляется блок проверок, срабатывающий только при `NODE_ENV === 'production'` и отвергающий эти же значения как заглушки.

---

## Проверки при старте в продакшене

Выполняются в `validateConfig` (`configuration.ts:45`) — там же, где уже находится условная проверка `OPENAI_API_KEY`.

1. **Заданность** (FR-016) — каждая критичная переменная присутствует.
2. **Отличие от заглушки** (FR-017) — значение не входит в перечень известных заглушек (см. [data-model.md](../data-model.md#6-перечень-критичных-секретов)).
3. **Минимальная длина** (FR-018) — 32 символа для машинно-генерируемых значений, 12 для `ADMIN_PASSWORD`.
4. **Уникальность** (FR-009e) — в `CLIENT_API_KEYS` нет повторяющихся меток и нет повторяющихся значений ключей.
5. **Непустой список источников** (FR-031) — `CORS_ALLOWED_ORIGINS` задан; разрешение произвольного источника в продакшене недостижимо.

**Поведение при нарушении:** процесс завершается с ненулевым кодом. Сообщение называет переменную и характер нарушения, **не печатая значение** (FR-019).

**Требование к полноте сообщения:** при нескольких нарушениях перечисляются все, а не первое найденное. Иначе развёртывание превращается в серию перезапусков, каждый из которых открывает ровно одну следующую проблему.

## Файлы окружения

**`.env.example`** — пополняется всеми новыми переменными с пояснениями и заведомо непригодными к использованию значениями-местозаполнителями.

**`.env.prod`** — пополняется новыми переменными и **тремя отсутствующими сейчас**: `ADMIN_USER`, `ADMIN_PASSWORD`, `ADMIN_COOKIE_SECRET`. Их отсутствие — причина того, что панель в продакшене работает на дефолтах из репозитория (см. [research.md](../research.md#r9-расхождение-в-сведениях-о-доступности-панели)). Значения проставляются на сервере; в репозиторий не коммитятся (файл покрыт `.gitignore:4`).

**`.env.test`** — пополняется валидным тестовым перечнем ключей, чтобы e2e-тесты обращались к защищённым маршрутам корректно, а не в обход проверки (R6).

## Ротация ключа LLM-провайдера (FR-022)

Действующий ключ AITunnel, находившийся в открытом виде в рабочей копии, подлежит замене; прежний отзывается у провайдера. Операция выполняется в личном кабинете провайдера и требует только обновления значения в конфигурации сервера — изменений в коде не нужно.

Проверка отзыва — контрольным обращением со старым ключом, ожидающим отказа (SC-008). Без этой проверки задача считается невыполненной: нахождение нового ключа в конфигурации ничего не говорит о судьбе старого.

## Развёртывание

`docker-compose.prod.yml:29` передаёт конфигурацию через `env_file: .env.prod` — механизм доставки не меняется, только состав переменных.

Отдельно от объёма данной задачи стоит отметить: `docker-compose.prod.yml:9-11` берёт `DB_USER` / `DB_PASSWORD` / `DB_NAME` из окружения оболочки с запасными значениями `assistant` / `assistant` / `ai_assistant`, а compose автоматически подхватывает `.env`, но не `.env.prod` — то есть в продакшене с высокой вероятностью действует пароль базы `assistant`. База наружу не публикуется (`docker-compose.prod.yml:41-43` — порты открывает только nginx), поэтому это не входит в перечень P0-блокеров, но заслуживает отдельной задачи.
