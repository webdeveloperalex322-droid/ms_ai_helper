# Implementation Plan: Status Management for Cities and Products

**Branch**: `feat/status-management` | **Date**: 2026-07-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-status-management/spec.md`

---

## Summary

Add operator-controlled `isActive` toggle to cities (already in schema, not yet enforced in API or editable in admin) and products (new DB field). Disabled city → zero products returned by API + import skips. Disabled product → excluded from all API responses globally. Changes span: DB migration, three SQL query services, AssistantOrchestratorService pre-flight, and two AdminJS resources.

---

**Scale/Scope**: Small number of cities (<100) and products (<10k). Pre-flight DB reads are cheap.

## Implementation Phases

### Phase A: DB Migration

1. Edit `src/database/schema/products.ts` — add `isActive: boolean('is_active').notNull().default(true)`
2. Run `pnpm db:generate` to generate migration file
3. Run `pnpm db:migrate` to apply

**Outcome**: `products.is_active` column exists with all rows = `true`.

---

### Phase B: SQL Query Filters

Add `cities.isActive = true` AND `products.isActive = true` to all three query services:

**VectorSearchService** (`src/modules/rag/services/vector-search.service.ts`):
- Already JOINs `city_products`. Add JOIN to `cities` on `city_products.br = cities.br` and `products` on `city_products.product_id = products.id`.
- Add WHERE: `cities.is_active = true`, `products.is_active = true`

**KeywordSearchService** (`src/modules/rag/services/keyword-search.service.ts`):
- Same JOIN + WHERE additions as vector search.

**CatalogService.findByCity()** (`src/modules/catalog/services/catalog.service.ts:25-102`):
- Already JOINs `products`. Add JOIN to `cities` and WHERE conditions for both `isActive` fields.

---

### Phase C: Orchestrator Pre-flight

In `AssistantOrchestratorService.handle()` — add before shortlist build:

```typescript
// 1. City active check
const city = await db.select({ isActive: cities.isActive })
  .from(cities)
  .where(and(eq(cities.rn, rn), eq(cities.br, br)))
  .limit(1);
if (!city[0]?.isActive) {
  return { cards: [], answer: '' };
}

// 2. Active products count check
const activeCount = await db.select({ count: count() })
  .from(products)
  .innerJoin(cityProducts, eq(cityProducts.productId, products.id))
  .where(and(
    eq(cityProducts.rn, rn), eq(cityProducts.br, br), eq(cityProducts.target, target),
    eq(products.isActive, true), eq(cityProducts.isAvailable, true)
  ));
if (activeCount[0].count === 0) {
  return { cards: [], answer: '' };
}
```

**Note**: The exact return shape must match the existing DTO — check `ProductAnswerResponseDto`.
