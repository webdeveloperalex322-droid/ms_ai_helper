# Contract: `GET /v1/assistant/suggestions`

**Feature**: 012-suggestions-mix | Изменение существующего эндпоинта. Обратная совместимость обязательна.

## Запрос

| Параметр | Тип | Обяз. | Изменение | Описание |
|----------|-----|-------|-----------|----------|
| `rn` | string (uuid) | да | — | сеть |
| `br` | string (uuid) | да | — | город |
| `target` | string | нет | — | канал, по умолчанию `WEB` |
| `screen_context` | string | нет | **расширено** | `catalog` (по умолчанию), `cart`, `checkout`, `empty`. Неизвестное значение трактуется как `catalog` |
| `session_id` | string (≤128) | нет | **новый** | единица стабильности и ротации набора. Без него набор не гарантирует стабильность при повторном запросе |

Пример:

```http
GET /v1/assistant/suggestions?rn=A79C5050-1EE7-11EB-9B6E-05B5FC40DF2A&br=<city-uuid>&target=WEB&screen_context=catalog&session_id=visit-9f3c
```

## Ответ `200 OK`

```json
{
  "suggestions": [
    {
      "id": "4f1b...",
      "code": "popular_rolls",
      "title": "🔥 Самые популярные роллы",
      "sort_order": 20,
      "kind": "product",
      "payload_preview": {
        "intent": "product_recommendation",
        "category": "roll",
        "tags": ["популярное"]
      }
    },
    {
      "id": "7c02...",
      "code": "delivery_cost",
      "title": "🚚 Сколько стоит доставка?",
      "sort_order": 310,
      "kind": "service",
      "payload_preview": { "intent": "info_question" }
    }
  ]
}
```

| Поле элемента | Изменение | Описание |
|---------------|-----------|----------|
| `id`, `code`, `title`, `sort_order` | — | как сейчас |
| `payload_preview` | — | как сейчас; у сервисных подсказок содержит только `intent` |
| `kind` | **новое** | `product` или `service`. Позволяет клиенту различать подсказки, которые ответят карточками, и те, что ответят текстом |

Совместимость: существующие поля не переименованы и не удалены, новое поле добавлено в конец объекта. Клиент, игнорирующий `kind`, продолжает работать.

## Гарантии ответа

| Требование | Гарантия |
|------------|----------|
| FR-008 | Длина `suggestions` ≤ лимита набора (по умолчанию 6) |
| FR-010 | В контексте `catalog`, если в городе есть пригодные сервисные подсказки, их в наборе 1–2; остальные — товарные |
| FR-011 | Если подсказок одного типа не хватает, набор дополняется другим типом |
| FR-012 | Два запроса с одинаковыми `rn`, `br`, `target`, `screen_context`, `session_id` в пределах одной части суток дают одинаковый состав и порядок |
| FR-013 | Повторов `id` нет |
| FR-014 | Пустой набор — `{"suggestions": []}` со статусом `200` |
| FR-015, FR-016 | Товарная подсказка без подходящих товаров города и сервисная подсказка в городе без проиндексированной базы знаний в ответ не попадают |
| FR-022 | Подсказка с `allowed_br` вне запрошенного города не попадает |
| SC-006 | p95 ≤ 300 мс |

Порядок элементов — по итоговому весу отбора по убыванию, при равенстве — по `sort_order` по возрастанию. Клиент выводит подсказки в полученном порядке.

## Ошибки

| Код | Когда |
|-----|-------|
| `400` | отсутствует `rn` или `br`, либо `session_id` длиннее 128 символов |
| `200` с пустым списком | нет пригодных подсказок; сбой статистики или проверок пригодности — ответ отдаётся без них (ADR-005) |

Эндпоинт не возвращает `5xx` из-за недоступности статистики, базы знаний или проверки наличия товаров.

## Связанные события

Клиент после отрисовки набора отправляет `POST /v1/assistant/events` с `event_type = suggestion_shown` на **каждую показанную** подсказку (с тем же `session_id`), а при выборе — `suggestion_clicked`. Без событий показа статистика (FR-024) не наполняется и отбор работает по порядку администратора.
