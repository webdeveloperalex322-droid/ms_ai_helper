## 2. Вычисляемые сущности (не хранятся)

### 2.1 `SuggestionStats`

Агрегат по `assistant_suggestion_events` за период, разрез `rn` + `target`.

| Поле | Тип | Правила |
|------|-----|---------|
| `suggestionId` | uuid | ключ |
| `shown` | int | число событий `suggestion_shown` за период |
| `clicked` | int | число событий `suggestion_clicked` за период |
| `ctr` | float | `clicked / shown`, достоверен только при `shown >= порог` |

Кеш в памяти, TTL 60 с на ключ `rn|target`. Отсутствие данных и ошибка запроса равнозначны: пустая статистика.

### 2.2 `SuggestionEligibility`

| Поле | Тип | Правила |
|------|-----|---------|
| `productsAvailable` | boolean | для товарной подсказки: число товаров города под её слоты `>= min_products_count`. Сбой проверки → `true` (FR-017) |
| `knowledgeAvailable` | boolean | для города: существует фрагмент `site_page_chunks` с `embedding_status = 'ready'`. Кеш TTL 5 минут на `rn|br`. Сбой → `false`, чтобы не показывать сервисную подсказку, которая гарантированно ответит отказом |

Товарная подсказка проверяется только по товарам, сервисная — только по базе знаний (FR-015, FR-016).

### 2.3 `DayPart`

| Поле | Тип | Правила |
|------|-----|---------|
| `current` | `lunch \| evening \| night \| other` | по часовому поясу из настройки; интервал через полночь — непрерывный |
| `scenarioMatches(scenario)` | boolean | `lunch → lunch`; `dinner`, `evening`, `movie` → `evening`; неизвестный сценарий и его отсутствие → вне сопоставления, множитель 1 |

### 2.4 `SelectionCandidate`

| Поле | Тип | Правила |
|------|-----|---------|
| `suggestion` | подсказка | прошедшая фильтры включённости, канала, контекста, окна показа, города и пригодности |
| `kind` | `product \| service` | из `payload.intent` |
| `base` | float | `1 / (1 + sort_order / 100)` |
| `ctrFactor` | float | `1 + вес * ctr` при достоверной статистике, иначе `1 + бонус исследования` |
| `dayPartFactor` | float | буст в своём окне, обратный буст вне него, `1` при отсутствии сопоставления |
| `contextFactor` | float | повышение для профильных подсказок контекста: дополнения в `cart`, сервисные в `checkout`/`empty` |
| `weight` | float | произведение множителей на `base` |

## 3. Правила валидации

- `screen_contexts` принимает только значения из перечисления; неизвестное — ошибка валидации в админском API.
- `calories_max` — положительное число либо `null`.
- Квота сервисных мест в контексте `catalog`: от 1 до 2 при наличии пригодных сервисных подсказок; при их отсутствии — 0, места отдаются товарным (FR-011).
- Набор не содержит повторов `suggestion_id` (FR-013).
- Размер набора: `min(лимит, число пригодных кандидатов)`; лимит по умолчанию 6 (FR-008).
- `session_id`: строка до 128 символов, необязательная; формат не проверяется.

```text
assistant_suggestions ──(payload.slots)──> products ⋈ city_products      # пригодность товарных
assistant_suggestions ──(intent=info_question)──> site_page_chunks       # пригодность сервисных

```
