# Implementation Plan: Product Attributes System

**Branch**: `005-product-attributes` | **Date**: 2026-07-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-product-attributes/spec.md`

## Summary

Add a product attributes system: import the Venus API attribute catalog (`/v1/attributes/PRODUCT`) into a `product_attributes` reference table, extract attribute values from product API responses and store as JSONB on the `products` table, feed attribute labels into RAG searchable text and chunk metadata, and apply attribute-based slot scoring in `HybridRetrieverService`.

Attributes in the Venus API are **label-based badges** (e.g. "42 шт.", "Пицца 35 см"), not typed key-value pairs. Each attribute has a UUID identifier and a human-readable name.

## Phase 0: Research (complete)

See [research.md](research.md) for all decisions. Key findings:
- Attribute API shape: label badges with UUID + name, no `code`/`valueType` fields
- GIN index syntax: `index('...').using('gin').on(table.attributes)`
- Product `attributes` field: `Array<{ id: string; name?: string }>` from API
- Normalized storage: `ProductAttributeValue[] = { id: string; name: string }[]`
- Scoring weight: +10 per matched attribute (same as tag bonus)

### Implementation Details

#### `product_attributes` table (new)
```typescript
pgTable('product_attributes', {
  id: uuid('id').primaryKey().defaultRandom(),
  rn: uuid('rn').notNull(),
  externalId: text('external_id').notNull(),   // attribute UUID from API
  name: text('name').notNull(),
  groupName: text('group_name'),
  isActive: boolean('is_active').notNull().default(true),
  rawPayload: jsonb('raw_payload'),
  updatedAt: timestamp('updated_at').notNull().defaultNow(),
}, (table) => ({
  rnExternalIdUniq: unique('product_attributes_rn_ext_id_uniq').on(table.rn, table.externalId),
  rnIdx: index('idx_product_attributes_rn').on(table.rn),
}))
```

#### `products` table additions
```typescript
// Column:
attributes: jsonb('attributes').$type<ProductAttributeValue[]>().default([]),

// Index (added to existing third-argument object):
attributesGinIdx: index('products_attributes_gin_idx').using('gin').on(table.attributes),
```

#### `AttributeImportService` (new)
```typescript
async importAttributes(rn: string): Promise<{ jobId: string; imported: number }>
```
Pattern: identical to `CategoryImportService` — create job, fetch, upsert loop, mark success/failed.

Upsert conflict target: `(rn, externalId)`. Set on conflict: `{ name, groupName, isActive, rawPayload, updatedAt }`.

#### `getAttributes` — HTTP client
```
GET /v1/attributes/PRODUCT?rn={rn}
```
Returns `AttributeApiResponse[]`. Use existing `HttpService` with force UTF-8 encoding (same pattern as `getProductsByCategory`).

#### Normalizer attribute extraction
```typescript
// raw.attributes is Array<{ id: string; name?: string }> or undefined
const attributes: ProductAttributeValue[] = (raw.attributes ?? []).map(a => ({
  id: a.id,
  name: (a.name ?? '').trim(),
}));
```

#### Searchable text addition
```typescript
if (product.attributes?.length) {
  const text = product.attributes.map(a => a.name).filter(Boolean).join(', ');
  if (text) parts.push(`Атрибуты: ${text}`);
}
```

Metadata addition (in `buildMetadata()`):
```typescript
attributes: product.attributes ?? [],
```

#### HybridRetriever attribute scoring
In the TypeScript scoring loop (after hydration), when a product has attributes:
```typescript
// attributeSlots: string[] — names extracted from parsed intent
for (const attr of product.attributes ?? []) {
  if (attributeSlots.some(s => attr.name.toLowerCase().includes(s.toLowerCase()))) {
    score += 10;
  }
}
```
Intent slot extraction for attributes: if `intentSlots.attributes` is defined (new optional field on intent), use it; otherwise skip attribute scoring gracefully (backward compatible).
