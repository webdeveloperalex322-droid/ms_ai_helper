# Data Model: Разрешение категории товара при подборе

**Date**: 2026-10-01 | **Plan**: [plan.md](./plan.md)

Изменений схемы БД и миграций нет. Ниже — существующие сущности в той части, которая задействована, и новые структуры уровня приложения.

## Существующие таблицы (без изменений)

### `categories` — [src/database/schema/categories.ts](../../src/database/schema/categories.ts)

| Поле | Тип | Роль в фиче |
|------|-----|-------------|
| `rn` | uuid | ключ выборки справочника |
| `br` | uuid | не используется при резолве: справочник общий для городов сети |
| `target` | text | ключ выборки справочника |
| `category_id` | text | **значение, которое лежит в `products.category_id`** — результат резолва |
| `slug` | text | кандидат для сопоставления; уникален в паре с `rn`+`target` |
| `name` | text | кандидат для сопоставления и отображаемое имя в тексте отказа |
| `is_active` | boolean | в резолв попадают только активные |

Индекс `categories_lookup_idx (rn, target, is_active)` покрывает запрос резолвера — дополнительных индексов не требуется.

### `products` — поле `category_id`

Текст; содержит `categoryId` из ответа каталога. На боевом API это id **подкатегории**, которого нет в справочнике (у «Роллы и суши» — четыре разных значения), в сидах — канонический слаг (`roll`). Поэтому основной связкой служит `products.category_name`, совпадающее с `categories.name`, а сравнение по id сохранено для сид- и mock-каталогов.

### `city_products`

Не затрагивается; фильтры доступности/цены/города работают как раньше.

## Новые структуры уровня приложения

### `ResolvedCategory`

Результат резолва одного названия категории.

| Поле | Тип | Описание |
|------|-----|----------|
| `categoryIds` | `string[]` | значения для фильтра по `products.category_id` — для каждой совпавшей категории и её `category_id`, и её `slug`; пусто — категория не распознана |
| `labels` | `string[]` | отображаемые имена совпавших категорий (для текста отказа, FR-010) |
| `matched` | `boolean` | `categoryIds.length > 0` |

Правила:
- `matched === false` ⇒ фильтр по категории НЕ применяется (FR-005).
- `categoryIds` не содержит дублей, порядок — как вернул справочник.
- Ошибка чтения справочника ⇒ `matched === false` (FR-008), исключение наружу не выбрасывается.

### `CategoryOption`

Элемент списка категорий, передаваемого распознавателю намерений.

| Поле | Тип | Описание |
|------|-----|----------|
| `slug` | `string` | служебное имя из справочника |
| `name` | `string` | отображаемое имя |

Правила: только активные категории (rn, target); максимум ~40 элементов; при пустом справочнике — исторический список `roll, set, drink, sauce, dessert, hot` (FR-008).

### Изменение `CatalogFilters`

[src/modules/catalog/services/catalog.service.ts](../../src/modules/catalog/services/catalog.service.ts)

| Было | Стало |
|------|-------|
| `categoryId?: string` | `categoryIds?: string[]` |

- Пустой массив и `undefined` эквивалентны «без ограничения по категории».
- В SQL: `inArray(products.categoryId, filters.categoryIds)`.
- Потребители (`ShortlistBuilderService`, `SuggestionService.checkProductsExist`, `HybridRetrieverService.computeScore`) обязаны передавать уже разрешённые идентификаторы; сырой слот в это поле попасть не может.

### Кэш справочника

Ключ `"<rn>|<target>"` → `{ items: CategoryRow[]; expiresAt: number }`, TTL 5 минут, хранится в памяти процесса. Промах/протухание ⇒ один SELECT по `categories`. Сбой SELECT ⇒ пустой справочник на этот вызов, запись в кэш не кладётся.

## Таблица синонимов (константа)

| Исторический слаг | Синонимы для сопоставления |
|-------------------|----------------------------|
| `roll` | roll, rolls, ролл, роллы |
| `set` | set, sets, сет, сеты |
| `drink` | drink, drinks, напиток, напитки |
| `sauce` | sauce, sauces, соус, соусы |
| `dessert` | dessert, desserts, десерт, десерты |
| `hot` | hot, горячее, горячие, горячие блюда |

Используется только если входное значение равно ключу; расширяется как данные, без изменения логики.
