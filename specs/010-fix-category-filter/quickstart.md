# Quickstart: проверка разрешения категории

**Date**: 2026-10-01 | **Plan**: [plan.md](./plan.md)

## Предусловия

- `pnpm install`, Postgres с pgvector поднят, миграции применены (схема фичей не меняется).
- Для боевой проверки: доступ к test-chat (`TEST_CHAT_*` в локальном `.env`) и клиентский ключ API.

## 1. Юнит- и интеграционные тесты (локально)

```bash
pnpm vitest run src/modules/catalog/tests/category-resolver.spec.ts
pnpm vitest run src/modules/catalog/tests/catalog-filters.spec.ts
pnpm vitest run src/modules/assistant/tests/shortlist-builder.spec.ts
pnpm test
```

Ожидаемо: все зелёные. Ключевые кейсы — в [contracts/category-resolver.md](./contracts/category-resolver.md).

## 2. Локальный прогон на сид-данных (регрессия)

```bash
pnpm db:seed
pnpm start:dev
```

```bash
curl -s -X POST http://localhost:3000/v1/assistant/product-answer \
  -H 'Content-Type: application/json' -H 'x-api-key: <ключ>' \
  -d '{"rn":"<rn>","br":"<br>","target":"WEB","user_message":"какие у вас есть роллы"}'
```

Ожидаемо: непустой `cards` (на сидах `category_id` совпадает со слагом — срабатывает уровень точного совпадения, поведение не деградировало).

## 3. Боевая проверка (главный критерий — дефект воспроизводится только на реальном каталоге)

Справочник категорий должен быть непуст. Если он пуст — сначала импорт категорий, затем переиндексация (`pnpm rag:index-all`).

Запросы через test-chat (`https://mshelper.al-developer.ru/test-chat/api/assistant/product-answer`, Basic Auth + `x-api-key`), `rn=A79C5050-1EE7-11EB-9B6E-05B5FC40DF2A`, `br=b8b3d1ac-4d3d-ea11-a958-8b023de8ef69`, `target=WEB`.

**Важно**: отправлять тело запроса в UTF-8 (через файл или скрипт), иначе кириллица в консоли Windows искажается и ответ будет не репрезентативен.

| Сообщение | До фикса | Ожидается после |
|-----------|----------|-----------------|
| «какие у вас есть роллы» | 0 карточек, `(из категории roll)` | ≥1 карточка, все — роллы (US1, SC-001/SC-002) |
| «подбери сет на компанию» | 0 карточек, `(из категории set)` | ≥1 карточка, все — сеты |
| «роллы до 500 рублей» | 0 карточек | ≥1 карточка, все дешевле 500 ₽ (FR-009) |
| «что есть с лососем» | 5 карточек | 5 карточек (регрессия не допускается) |
| «привет» | текст про помощь по меню | без изменений |
| «фывапролдж» (несуществующая категория) | — | ответ без жёсткого отказа по категории (FR-005) |

Список подсказок:

```
GET /v1/assistant/suggestions?rn=<rn>&br=<br>&target=WEB
```

Ожидаемо: присутствуют подсказки с категорией («Популярные роллы», «Подобрать сет»), нажатие возвращает карточки (US2, SC-003).

## 4. Проверка производительности

Сравнить `POST /v1/assistant/product-answer → 200 (<N>ms)` в логах контейнера до и после. Рост не более 10% (SC-005). Второй и последующие запросы идут по кэшу справочника.

## 5. Если карточек по-прежнему нет

Признак: в ответе снова `(из категории …)` при непустом каталоге.

1. Проверить, что справочник `categories` для (rn, target) заполнен.
2. Сверить реальные `slug`/`name` с таблицей синонимов в [data-model.md](./data-model.md) — при промахе расширить синонимы (правка константы, логика не меняется).
3. Убедиться, что пустой резолв не превращается в жёсткий фильтр (FR-005) — это и был исходный дефект.
